# Task 8.1 — Canonical payment model and safe persistence

## Paths and file-level plan
- `types.ts`: optional contract/supplier/schedule/payment/allocation fields, aggregate summary types; retain legacy actualCost.
- `lib/budgetPayments.ts`: pure validated integer-money ledger, T±N date helpers (Asia/Bangkok date), shared summaries, allocation, schedule edits, void and historical reconciliation.
- `store/useStore.ts`: atomic current-state mutations for item edits, payments and schedules; retain dirty/revision sync and PIN local mode. Ephemeral dashboard-to-budget filter.
- `lib/backup.ts`: validate new nested fields before mutation; retain old backup compatibility and full round-trip.
- `services/cloudService.ts`: reject malformed financial extensions on reads/saves; existing JSONB RPC retains payload without SQL changes.
- `tests/budgetPayments.test.ts`, `tests/budgetPersistence.test.ts`: partial/deposit/overpay/no-price/legacy/date/void/restore/validation/race boundaries.

## Best practices / acceptance
Never infer actual cash from legacy status or actualCost. One shared total computation; exact nonnegative safe integer VND. Per-supplier balances, independent work status, no duplicated allocations. Preserve history when voiding; never silently delete transactions. Fail closed for malformed new records.
